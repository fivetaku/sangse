# 입력 체크리스트 — 할루시네이션 게이트

> 이 파일의 존재 이유: 사례·수치·후기·환불 규정이 없을 때 Claude가 "그럴듯한 문장"으로 빈칸을 메우는 것을 구조적으로 막는다. 워크스페이스 원칙 "No Hallucination"과 영상의 "현실 가능한 약속만"이 여기서 만난다.

## 1. 필수 입력 4종 (하나라도 없으면 카피 생성을 시작하지 않는다)

| # | 항목 | 왜 필수인가 | 부족할 때 질문 예시 |
|---|---|---|---|
| M1 | **무엇을 파는가** (제품/서비스 한 줄) | 없으면 페이지 자체가 성립 안 함 | "한 줄로 말하면 무엇을 파는 건가요?" |
| M2 | **누구에게** (좁은 타겟) | "모두"면 Q1이 성립하지 않음 → 아무에게도 후킹 안 됨 | 아래 §3 타겟 좁히기 |
| M3 | **가격 또는 가격 구조** | Q8·Q2가 가격에 의존. "협의"·"미정"도 허용(그 경우 배지로 대체) | "가격은 얼마인가요? 미정이면 '미정'이라고 답해도 됩니다" |
| M4 | **고객이 얻는 변화 한 줄** | 창업자가 스스로 약속을 정의하지 못하면 AI도 정할 수 없다(영상: "약속은 AI가 정해줄 수 없다") | "이걸 쓴 고객은 언제, 무엇이 어떻게 달라지나요?" |

## 2. 8질문 슬롯 (있으면 채우고, 없으면 플레이스홀더)

| 슬롯 | 채우는 섹션 | 상태 표기 | 없을 때 처리 |
|---|---|---|---|
| S1 고객의 고민 장면 (구체적 순간) | Q1 | 채움 / 추정 | 사용자 M2·M4에서 **추정**해 3개 제시 → 승인받은 것만 사용. 카피에 `(추정)` 표기 없이 쓰되 `intake-checklist.md`에 추정 출처 기록 |
| S2 결과물·수치·전후 | Q2 | 채움 / 없음 | 수치 없음 → 정성적 도착 장면만 쓴다. **새 숫자 생성 금지** |
| S3 기존 방식의 한계 + 우리 메커니즘 + 핵심 기능 | Q3 | 채움 / 부분 | 기능만 있고 한계가 없으면 "기존에 이 문제를 어떻게 해결하고 있었나요?" 1회 질문 |
| S4 사례·후기·스크린샷·결과물 샘플 | Q4 | 채움 / 없음 | `[자료 필요: 실제 결과물 화면 1장 또는 후기 1~2개]` 플레이스홀더 + 정직한 대체 문구 제안("첫 30명 체험단 모집 중" 등은 **사용자가 실제로 할 의사가 있을 때만**) |
| S5 소요 시간·단계·지원 도구 | Q5 | 채움 / 없음 | 단계는 제품 설명에서 유도 가능. 시간 수치는 없으면 쓰지 않는다 |
| S6 구성품·지원 범위 | Q6 | 채움 / 부분 | 목록을 여정 순서로 재배열. 없는 구성품 추가 금지 |
| S7 환불·보증·피드백 범위 | Q7 | 채움 / 없음 / 환불불가 | 없음 → "환불 규정이 있나요? 없다면 어떤 조건이 가능할까요?" 1회 질문. 환불불가 → 그대로 명시하고 다른 리스크 감소 장치(샘플·미리보기·FAQ)로 보강. **"100% 만족 보장" 같은 미확인 문구 생성 금지** |
| S8 마감·할인·한정 조건 | Q8 | 채움 / 없음 | 없음 → 가짜 긴급성 만들지 않는다. CTA만 두고 `[선택: 기한·한정 장치를 넣으려면 조건을 알려주세요]` |
| S9 플랫폼 (웹 랜딩 / 스마트스토어 / 크몽 / 기타) | 전체 형식 | 채움 / 기본값 | 기본값 웹 랜딩. 이미지 비율과 HTML 폭이 달라지므로 첫 질문 묶음에 포함 |
| S10 톤·브랜드 (색·분위기·기존 로고) | 이미지 | 채움 / 기본값 | 기본값: 깔끔한 화이트 배경, 브랜드 1색 강조 |

## 3. 타겟 좁히기 절차 ("모두를 위한"이 들어왔을 때)

1. 거부하지 말고 이유를 한 줄로 설명한다: "모두에게 좋을 수 있지만 첫 페이지는 가장 아픈 사람 한 명만 찌를 때 팔립니다."
2. M1·M4를 근거로 **가장 강한 페인포인트를 가진 고객 장면 3개를 추정 제시**하고 하나를 고르게 한다(AskUserQuestion, 옵션에 "내가 직접 쓸게" 포함).
3. 사용자가 끝까지 "모두"를 고집하면 그 결정을 따르되 `intake-checklist.md`에 "사용자 결정: 광범위 타겟"을 기록하고 Q1은 가장 보편적인 장면 1개로 쓴다.

## 4. 질문 묶음 규칙

- AskUserQuestion은 **착수 시 1콜, 최대 4문항**. 우선순위: 필수 4종 중 빠진 것 → S9 플랫폼 → S7 환불 → S4 사례 유무.
- 4문항을 넘는 부족분은 묻지 않고 플레이스홀더로 진행한다. 카피 완료 보고에 "채우면 완성되는 항목" 표로 정리한다.
- 같은 질문에 답이 없으면 재질문하지 않는다. 디폴트를 선언하고 진행한다.

## 5. 입력 형태별 수집 방법

| 형태 | 방법 | 주의 |
|---|---|---|
| 붙여넣은 텍스트 | 그대로 `raw-input.md`에 저장 | 정리 안 된 메모도 OK |
| 로컬 파일 (md/txt/pdf) | Read로 읽어 발췌를 `raw-input.md`에 병합 | PDF는 Read가 페이지 단위로 지원 |
| URL | WebFetch → 실패(403 등) 시 insane-search 스킬 | 경쟁사 URL은 **참고용**. 경쟁사 수치·후기를 우리 것으로 옮기지 않는다 |
| 기존 상세페이지 | 창업자 언어 문장을 추출해 번역 대상 목록으로 삼는다 | 기존 페이지의 수치는 사용자 확인 후 사용 |

## 6. 출처 추적 규칙

`copy.md`의 모든 수치·고유명사·인용문은 `raw-input.md` 또는 사용자 답변에서 찾을 수 있어야 한다. 검수 단계에서 grep으로 대조한다(→ `review-checklist.md` §2).

## 7. intake-checklist.md 산출물 형식

```markdown
# Intake — {slug}
| 슬롯 | 상태 | 내용 요약 | 출처 |
|---|---|---|---|
| M1 무엇 | 채움 | ... | raw-input.md L3 |
| M2 누구 | 추정→승인 | 30대 프리랜서 디자이너, 크몽 첫 등록 | 사용자 답변 Q-2 |
| ... |
## 채우면 완성되는 항목
- S4 사례: 실제 결과물 스크린샷 1장
- S8 기한: 런칭 할인 조건
```
