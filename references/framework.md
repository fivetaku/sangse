# 8질문 프레임워크 — 상세페이지 구조 정본

> 출처: 다크 파운더 「매출 떡상하는 상세페이지의 비밀」(https://youtu.be/zJzdTyDxxi8, 2026-09-02). 워크스페이스 분석 문서: `ideation-workspace/30-research/2026-09-02-매출-떡상-상세페이지-작성법-영상분석.md`

## 한 줄 정의

상세페이지는 설명서가 아니라 **고객이 결제 전에 조용히 던지는 8가지 질문에 순서대로 답하는 영업사원**이다. 예쁘기만 하고 결제가 안 나는 페이지는 "예쁜 쓰레기"다.

## 원칙 9개

1. **주인공은 고객.** 창업자도 서비스도 아니다. 구매를 망설이는 고객이 주인공이면 순서·카피·가격 설명·후기·버튼 문구가 전부 달라진다.
2. **창업자 언어를 고객 언어로 번역한다.** 자랑을 없애는 게 아니다. "20년 경력"을 "그 경력이 당신의 이 문제를 어떻게 풀어주는가"로 바꾼다.
3. **첫 장면은 고객의 장면.** 제품명·브랜드·"AI 기반"으로 시작하지 않는다. 고객이 오늘 겪는 고민의 순간으로 시작한다.
4. **기능은 마지막 근거.** 고민을 먹는 훅을 먼저 잡고, 기능은 "그래서 이게 가능하다"는 증거로 Q3에서 등장시킨다.
5. **가치 4요소.** 결과가 선명 / 나도 가능해 보임 / 빨리 체감 / 수고가 적음. 넷이 갖춰질수록 가격은 덜 중요해진다.
6. **오퍼를 카피보다 먼저 고친다.** 오퍼 = 고객이 받는 것 + 줄어드는 불안 + 지금 선택해야 하는 이유의 전체 약속. 오퍼가 약하면 카피만 바꿔도 클릭은 오르고 결제는 안 난다.
7. **필요 없는 말을 걷어낸다.** 글을 더하지 말고, 구매 결정에 필요 없는 문장을 뺀다.
8. **현실 가능한 약속만, 그러나 후킹되게.** 과장은 단기 전환율이 높지만 브랜드를 망친다. 지킬 수 있는 약속과 후킹 사이의 간극을 문장력으로 메운다.
9. **한 번에 하나씩 바꾸고 로그를 남긴다.** 상단→중단→하단 순으로 A/B. 숫자와 함께 고객의 언어(VoC)도 모은다.

## 안티패턴 (첫 화면·본문에서 발견되면 즉시 수정)

| 안티패턴 | 예시 | 고객의 반응 |
|---|---|---|
| 기능 나열 | "AI 기반, 빠른 분석, 개인화, 올인원" | "그래서 나한테 왜 필요한데?" |
| 제품명·브랜드로 시작 | "○○은 AI 기반 사주 분석 서비스입니다" | AI가 해준다는 사실이 오히려 마이너스가 될 수 있음 |
| 스펙 자랑 | "국내 최초", "특허 보유", "20년 경력" | "그래서 내 문제를 어떻게 풀어주는데?" |
| 구성 나열 | "50강, PDF 20장, 커뮤니티" | "내가 결과를 낼 수 있는지가 궁금한데" |
| 전원 타겟 | "누구에게나 좋아요" | 아무에게도 후킹되지 않음 |
| 추상 결과 | "성공하세요", "삶이 달라집니다" | 눈앞에 잡히는 장면이 없음 |

## 8질문 = 섹션 순서

각 섹션은 `필요한 재료`가 사용자 입력에 있을 때만 구체적으로 쓴다. 없으면 지어내지 말고 `[자료 필요]` 플레이스홀더를 남긴다(→ `review-checklist.md`).

| # | 고객의 질문 | 섹션의 임무 | 필요한 재료 | 이미지 역할 |
|---|---|---|---|---|
| Q1 | 이게 나를 위한 건가? | 첫 화면에 제품명 대신 **고객의 구체적 장면**. 가장 강한 페인포인트를 가진 좁은 타겟 하나만 찌른다 | 페르소나, 고민 장면 문장 | 히어로: 고민 장면 또는 도착 장면. 텍스트는 헤드라인 1줄 |
| Q2 | 그래서 나는 뭘 얻나? | 서비스 이용 후 **도착하는 장면**을 눈앞에 잡히게. "성공"이 아니라 "월 100만 원", "3일 뒤 첫 상담" 수준 | 결과물, 수치, 전후 | 전후 비교 / 결과물 장면 |
| Q3 | 왜 이 방식이어야 하나? | 기존 방식의 한계 → 우리가 다르게 해결한 메커니즘. **기능은 여기서 근거로** | 기존 대안의 한계, 차별 메커니즘, 핵심 기능 | 메커니즘 다이어그램 / 비교표 |
| Q4 | 정말 나도 가능할까? | 사례, **결과물 미리보기(티저)**, 전후 변화, 실제 진행 화면. 후기보다 "실제 받아보는 화면"이 강함 | 사례, 스크린샷, 결과물 샘플, 후기 | 결과물 미리보기 목업 (사용자 실물 스크린샷이 최우선) |
| Q5 | 얼마나 힘들고 오래 해야 하나? | 단계를 보여주고 템플릿·피드백·매뉴얼로 **수고와 시행착오가 줄어든다**고 설득 | 소요 시간, 단계, 지원 도구 | 3~4단계 타임라인 |
| Q6 | 정확히 뭘 받나? | 목록이 아니라 **고객 여정 순서**: 먼저 받는 것 → 하는 것 → 막힐 때 지원 → 최종 결과물 | 구성품, 지원 범위 | 구성품 플랫레이 / 여정 스텝 |
| Q7 | 실패하면 어떡하지? | 과장 대신 **리스크 감소 장치**: 환불 규정, 피드백 범위를 정확히 | 환불·보증 정책, 지원 범위 | 보증 배지 (텍스트 짧게) |
| Q8 | 왜 지금 결제해야 하나? | 기한·한정·할인 등 **디테일한 장치** + CTA. 앞 7개가 쌓였으면 결제는 자연스러운 결론 | 마감, 할인, 한정 조건, 가격 | CTA 배너 |

## 선택 블록과 변수 (리서치 보완, 근거는 `evidence.md`)

- **Q7-FAQ (선택)**: Q7 아래 "실제 문의 기반 FAQ 3~5문항". 배송·교환·AS·호환·규제 표기 같은 거래형 질문은 서사 흐름에 안 들어가므로 여기서 답한다. 물성 상품·스마트스토어·펀딩이면 기본 ON, 지어낸 질문 금지 — 입력에 문의 기록이 없으면 `[자료 필요: 실제 문의 상위 5개]`.
- **Q6 사양 표**: 여정 순서 서술 아래에 성분·용량·규격·호환 표를 둔다. 스펙이 없으면 고객은 경쟁 페이지로 이탈한다.
- **유입 경로 변수**: 검색·재방문 유입(제품을 이미 아는 고객)이 주면 Q1 헤드라인에 카테고리 키워드를 넣고 가격을 첫 화면 근처에 둔다. 광고 콜드 유입이 주면 원칙대로 고민 장면으로 시작한다. 순서는 바꾸지 않고 Q1의 문장 유형만 바꾼다.
- **CTA 반복**: 같은 CTA 문구를 Q2 끝·Q4 끝·Q8에 둔다. 페이지의 전환 목표는 하나다.
- **가독성**: 모바일 첫 화면 안에서 헤드라인이 완결되게, 문장은 중학생 수준으로. 전문 용어는 Q3 근거로 내려보낸다.

## 카피 작성 규칙

- **기능→변화 번역식**: 모든 기능 문장은 `[기능] 덕분에 [고객이 겪던 장면]이 [결과]로 바뀝니다` 꼴로 재작성 가능해야 한다. 안 되면 그 기능은 Q3 근거 목록으로 내려보낸다.
- **자랑 번역식**: `[스펙/경력/최초]` → `그 [스펙] 덕분에 당신은 [구체적 이득]을 얻습니다`.
- **첫 화면 금지어**: 제품명 단독, "AI 기반", "국내 최초", "올인원", "혁신적인", "누구나".
- **수치·사례·후기는 입력에 있는 것만.** 반올림·재표현은 가능하지만 새 숫자는 만들지 않는다.
- **CTA 버튼 문구**는 행동+결과: "구매하기" 대신 "첫 상담 질문지 받기", "내 매출 진단 시작".
- **길이**: 섹션당 헤드라인 1줄(20자 내) + 본문 2~5문장. 길다고 좋지 않다. 스크롤하고 싶은 문장만 남긴다.

## 영상 속 시범 흐름 (강의 상품)

1. 훅: "서비스 만들었는데 매출이 안 나죠? 그거 제가 해결해 줄게요."
2. 증거: 본인 매출 수치 + 결제 캡처
3. 차별 이유: "남들과 똑같이 만들어도 제가 팔리는 이유는 ○○○"
4. 너도 가능: "이 과정을 이미 겪었으니 따라오면 된다"
5. 오퍼 재설계: "명리학 50강" → "상담 전 질문지 + 상담 흐름 매뉴얼 + 첫 고객 마케팅 설계"
