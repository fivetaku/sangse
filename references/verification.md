# 검증 3중 게이트 — 만든 사람이 만든 것을 검사하지 않는다

> 카피 초안(Step 4) 뒤에 게이트 1·2, HTML 조립 뒤에 게이트 3을 통과해야 "완료"다. 게이트는 순서대로이며, 앞 게이트가 FAIL이면 뒤로 가지 않는다. 결과는 전부 `sangse/{slug}/qa/`에 남긴다.

## 게이트 1 — 자동 검사 (결정론적, 코드가 판정)

```bash
python3 ~/.claude/skills/sangse/scripts/check_copy.py "sangse/{slug}" --category {common|food|health_food|cosmetics ...} --platform {web|smartstore|kmong}
```

| ID | 판정 | 실패 시 |
|---|---|---|
| C1 | Q1~Q8 헤딩 8개, 순서 | 헤딩 수정 |
| C2 | Q1에 첫 화면 금지어("AI 기반", "국내 최초", "올인원", "누구나") 없음 | Q1을 고객 장면으로 다시 |
| C3 | copy.md의 모든 숫자가 raw-input/intake에 존재. 파생 수치는 intake에 `파생: 300 mL = 10 mL × 30포` 계산식 필요 | 숫자 삭제 또는 출처 기록 |
| C7 | 헤드라인 20자 이내 | 줄이기 |
| C8 | CTA 3개 이상·문구 동일·행동+결과 | CTA 통일 |
| C9 | `assets/banned-words.json` 카테고리 금지어 없음 (ban=FAIL, warn=WARN) | compliance.md 치환표로 번역 |
| C10 | Q6 사양 표, 물성 플랫폼이면 Q7 FAQ | 추가 |
| I | images.json의 파일 실존 | 재생성 또는 `[이미지 생성 실패]` |

exit 0이 아니면 게이트 2로 가지 않는다. WARN은 문맥을 보고 review-log에 판단 이유를 한 줄 남긴다. 산출: `qa/check_copy.json`.

## 게이트 2 — 고객 시뮬레이션 리뷰 (에이전트 4인 병렬, 작성자와 분리)

카피를 쓴 Claude가 아니라 **별도 에이전트 4개**가 `copy.md`·`raw-input.md`·`intake-checklist.md`만 보고 판정한다. 프롬프트 골격은 §5. 4개를 한 메시지에 동시에 스폰한다.

| 리뷰어 | 페르소나 | 판정 축 |
|---|---|---|
| 의심 많은 고객 | intake M2의 타겟 그대로(연령·상황·오늘 겪는 장면). "그래서 나한테 뭐가 좋은데?"를 모든 문장에 붙임 | Q1~Q8 각각 **네/아니오** + 아니오의 이유가 되는 문장 인용 + 고객 언어로 재작성 제안 |
| 규제 심사관 | 식약처·공정위 심의 담당자 관점 (`compliance.md` §1~§3·§7 기준) | 위반 의심 문장·조문·수정안. 심의 통과 여부 |
| CRO 리뷰어 | `evidence.md` 기준으로 첫 화면·가독성·CTA·사회적 증거·스펙 유무 채점 | 항목별 1~5점, 근거 |
| 경쟁사 마케터 | 같은 카테고리 경쟁 제품 담당자. 이 페이지에서 가격 비교로 끌어갈 수 있는 틈을 찾음 | "우리라면 이렇게 반박한다" 3개 + 방어 문장 제안 |

**통과 기준**: 의심 많은 고객이 Q1~Q8 전부 "네" + 규제 심사관 위반 0건. 미달이면 지목된 문장만 고쳐 **최대 2라운드** 재리뷰(전면 재작성 금지). 2라운드 뒤에도 "아니오"가 남으면 그 항목을 사용자에게 보고하고 결정을 넘긴다.

Chairman(메인 Claude)이 4개 결과를 `qa/sim-review-r{n}.md`로 합치고, 수정 문장은 `review-log.md`에 `원문 → 수정문 (리뷰어)` 형태로 기록한다.

## 게이트 3 — 렌더 검증 + 5초 테스트 (HTML 조립 뒤)

1. 스크립트로 실제 브라우저 렌더 + 계측을 한 번에 한다:
   ```bash
   python3 ~/.claude/skills/sangse/scripts/render_check.py "sangse/{slug}" --widths 390,860 --full
   ```
   Playwright viewport 에뮬레이션으로 `qa/render-390.png`·`qa/render-860.png`(첫 화면)와 `-full.png`(전체)를 저장하고, 가로 스크롤·Q1 헤드라인 첫 화면 내 위치·첫 CTA가 두 화면 안인지·깨진 이미지 수를 `qa/render_check.json`에 기록한다. FAIL이면 exit 1.
   **함정**: 헤드리스 Chrome CLI(`--window-size=390,…`)는 최소 창 폭이 500px라 390 스크린샷이 오른쪽이 잘린 것처럼 나온다(2026-09-02 실측: `innerWidth=500`). 이걸 레이아웃 결함으로 오판하지 말 것 — 반드시 viewport 에뮬레이션(Playwright·paseo resize)을 쓴다.
2. 스크린샷을 **Read로 직접 본다**(계측 JSON만 믿지 않는다): 이미지 안 한글이 깨지지 않았는가 / 표가 표로 렌더됐는가 / 노란 플레이스홀더가 숨겨지지 않았는가 / 히어로 텍스트가 잘리지 않았는가.
3. **5초 테스트**: `qa/render-390.png` **1장만** 새 에이전트에 Read 시키고(다른 파일 금지) 세 질문을 던진다 — "무엇을 파는 페이지인가 / 누구를 위한 것인가 / 사면 무엇이 달라지는가". 세 답이 intake의 M1·M2·M4와 맞으면 통과. 하나라도 못 맞히면 Q1 헤드라인·히어로 이미지 텍스트를 고치고 재렌더한다. 결과는 `qa/five-second.md`.
4. 스마트스토어·크몽이면 실제 등록 화면에 붙여 넣기 전 폭(860/720)과 이미지 용량(장당 20 MB 이하, 권장 2 MB 이하)을 확인한다.

## 5. 리뷰어 프롬프트 골격 (게이트 2)

공통 머리말: "너는 이 상세페이지를 쓴 사람이 아니다. 아래 파일만 읽고 판정하라: {copy.md 경로}, {raw-input.md}, {intake-checklist.md}. 칭찬은 쓰지 말고 문제만 문장 인용과 함께 써라. 마지막 줄에 `VERDICT: PASS|FAIL`을 적어라."

- **의심 많은 고객**: "너는 {M2 타겟 서술}이다. 오늘 {S1 고민 장면}을 겪었다. 이 페이지를 위에서부터 읽으며 각 섹션 끝에서 '이게 나를 위한 건가 / 뭘 얻나 / 왜 이 방식 / 나도 될까 / 얼마나 힘든가 / 뭘 받나 / 실패하면 / 왜 지금'에 네·아니오로 답하라. 아니오면 그 이유가 된 문장을 그대로 인용하고, 네가 듣고 싶었던 문장을 네 말투로 써라. 표 형식: 섹션 | 네/아니오 | 걸린 문장 | 원하는 문장."
- **규제 심사관**: "너는 {카테고리} 표시·광고 심의 담당자다. compliance.md({경로}) §1~§3·§7 기준으로 위반·위반 의심 문장을 조문 번호와 함께 전부 열거하고 수정안을 써라. 없으면 '위반 없음'이라 쓰되 경계 표현 3개를 골라 근거를 대라."
- **CRO 리뷰어**: "evidence.md({경로})의 기준으로 채점하라: 첫 화면 가치제안(10초 안에 이해되는가) / 가독성(중학생 수준인가) / CTA(단일·반복·행동+결과) / 사회적 증거(실물 우선, 없으면 정직한 플레이스홀더인가) / 스펙(사양 표 충분한가) / 인식 단계 일치(유입 경로에 맞는 첫 화면인가). 각 1~5점과 근거, 가장 먼저 고칠 1개."
- **경쟁사 마케터**: "너는 {카테고리}에서 더 싼 경쟁 제품의 마케터다. 이 페이지를 읽고 고객을 가격 비교로 끌어갈 수 있는 틈 3개를 찾아 '우리라면 이렇게 말한다'를 쓰고, 각 틈을 막을 방어 문장을 이 페이지 톤으로 제안하라. 없는 사실을 지어내 방어하지 마라."

## 6. 왜 3중인가

- 게이트 1만 있으면 문장이 "맞지만 안 팔리는" 상태를 못 잡는다.
- 게이트 2만 있으면 에이전트가 숫자 출처·금지어를 놓친다. 코드가 먼저 걸러야 리뷰어가 설득력에 집중한다.
- 게이트 3 없이는 이미지 안 한글 깨짐, 첫 화면 밖으로 밀린 헤드라인, 가로 스크롤을 못 본다. 실제 렌더를 본 것만 검증이다.
- 그래도 이 셋은 전부 **출시 전 대리 지표**다. 진짜 검증은 출시 후 A/B다(Step 11의 첫 가설이 그 시작).
