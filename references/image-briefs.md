# 이미지 브리프 — /pumasi:image 호출 규격

> 이미지 생성은 **반드시 Skill 도구로 `pumasi:image`를 호출**한다. codex exec·imagen.sh를 직접 부르지 않는다(프록시 우회·실패 사유 표면화가 그 스킬 안에 있다). 이 파일은 "무엇을 어떤 순서로 어떻게 부탁할지"만 정한다.

## 1. 실행 순서 (카피 확정 뒤에만)

1. `copy.md`가 사용자 승인을 받은 뒤에 시작한다. 카피 방향이 틀렸는데 이미지 8장을 뽑는 낭비를 막기 위해서다.
2. `image-briefs.md`를 먼저 쓴다: 섹션별 목적·비율·핵심 텍스트(12자 이내)·장면 서술. 사용자에게 장수와 예상 시간(1장 약 1분)을 알린 뒤 진행한다.
3. **앵커 우선**: Q1 히어로 1장을 먼저 생성한다. 결과 경로를 받아 나머지 장을 전부 `--ref {앵커 경로}`로 물린다. 앵커가 있으면 스타일 서술을 걷어내고 "첨부 이미지의 스타일·조명·색감 유지" + 피사체·구도 델타만 쓴다.
4. 각 호출 결과의 `path:`를 `image-briefs.md`에 기록한다. 실패한 장은 `[이미지 생성 실패 — 재시도 필요]`로 표기하고 다음 장으로 넘어간다. 파이프라인을 막지 않는다.
5. 텍스트가 든 장(히어로·CTA)은 생성 후 Read로 1장씩 검수한다(pumasi:image의 review 모드). 텍스트 없는 장은 검수 생략(fast 모드)으로 토큰을 아낀다.

## 2. 질문 폭발 억제 — 호출 인수에 반드시 넣을 키워드

`pumasi:image`는 백엔드·비율·퀄리티·의도 3개를 AskUserQuestion으로 묻는다. 매 호출마다 4~5문항이 뜨면 8장에 40문항이 된다. 아래 키워드를 args에 포함하면 해당 질문이 스킵된다.

| 스킵 대상 | 넣을 키워드 | 근거 |
|---|---|---|
| 백엔드 | `코덱스로` | 입력에 지명이 있으면 스킵 |
| 비율 | `세로 9:16` / `가로 16:9` / `정방형 1:1` / `배너 4:1` | keyword-mapping 자동 매핑 |
| 퀄리티 | `고품질` (최종) / `시안` (초안) | keyword-mapping 자동 매핑 |
| 의도 3개 | 브리프에 스타일·배경·구도를 **문장으로 명시** | 의도가 입력에 확정돼 있으면 질문 슬롯이 줄어든다 |

호출 args 골격:

```
코덱스로 {비율} {퀄리티} 제품 이미지 — 상세페이지 {Qn} 섹션용.
장면: {고객 장면 또는 결과물 서술 1~2문장}.
스타일: {사실적 사진 | 플랫 일러스트 | 3D 목업} , 배경: {화이트 스튜디오 | 실제 사용 환경}, 구도: {정면 | 45도 | 탑다운}.
텍스트: "{12자 이내 헤드라인}" 을 굵은 산세리프로 상단에 (텍스트 없으면 "텍스트 없음").
저장 slug: {slug}-q{n}. 참조: {앵커 경로 또는 없음}.
```

## 3. 플랫폼별 비율

| 플랫폼 | 히어로 | 본문 이미지 | HTML 폭 |
|---|---|---|---|
| 웹 랜딩 (기본) | 가로 16:9 | 가로 16:9 또는 정방형 1:1 | 최대 720px, 모바일 우선 |
| 스마트스토어 | 세로 9:16 | 세로 9:16 (세로 스크롤형) | 860px (네이버 권장 가로폭) |
| 크몽 | 가로 16:9 (썸네일) | 정방형 1:1 | 최대 720px |
| 인스타 세일즈 | 정방형 1:1 | 정방형 1:1 | 해당 없음 |

## 4. 섹션별 이미지 역할과 기본 세트

기본은 **필수 4장**만 생성한다. 사용자가 "전부"라고 하면 선택 4장을 추가한다.

| 섹션 | 필수/선택 | 이미지 역할 | 텍스트 (12자 이내) | 피할 것 |
|---|---|---|---|---|
| Q1 이게 나를 위한 건가 | 필수 (앵커) | 고객의 고민 장면 또는 도착 장면. 인물이 있으면 타겟과 같은 연령·상황 | 헤드라인 1줄 | 제품 로고 단독, 기능 아이콘 나열 |
| Q2 나는 뭘 얻나 | 필수 | 전후 비교 또는 결과물이 놓인 장면 | 숫자 1개 또는 없음 | 그래프에 가짜 수치 |
| Q3 왜 이 방식 | 선택 | 메커니즘 3단계 다이어그램 | 단계명 3개(각 4자 이내) | 긴 설명문 |
| Q4 나도 가능할까 | 필수 | 결과물 미리보기 목업(화면·문서·패키지). **사용자 실물 스크린샷이 있으면 생성하지 않는다** | 없음 | 가짜 후기 말풍선, 가짜 인물 실명 |
| Q5 얼마나 힘들고 오래 | 선택 | 3~4단계 타임라인 | 단계명 | 구체 시간 수치(입력에 없으면) |
| Q6 정확히 뭘 받나 | 필수 | 구성품 플랫레이 또는 여정 스텝 | 구성품 이름 3~4개 | 입력에 없는 구성품 |
| Q7 실패하면 | 선택 | 보증 배지 | "7일 환불" 등 정책 그대로 | 정책과 다른 문구 |
| Q8 왜 지금 | 선택 | CTA 배너 (배너 4:1 또는 플랫폼 비율) | CTA 문구 | 입력에 없는 할인·기한 |

## 5. 저장 경로와 HTML 연결

- `pumasi:image`는 git root 기준 `images/{YYYY-MM-DD}/{slug}-{seq}.png`에 저장한다. 산출물 폴더 `sangse/{slug}/`와 물리적으로 다르다.
- 결과 `path:`를 `sangse/{slug}/images.json`에 `{"Q1": "…png", "Q2": "…png"}`로 기록한다. `assemble_html.py`가 index.html 기준 상대경로로 변환한다.
- 파일을 재인코딩·리사이즈하지 않는다(pumasi:image 후처리 금지 원칙). 산출물 폴더로 바이트 그대로 복사(`cp`)하는 것은 허용 — 예시 배포·다른 저장소 이동 시 상대경로가 끊기지 않게 하기 위해서다.

## 6. 텍스트 렌더 한계 (gpt-image-2, 2026-05 기준)

- 할 수 있다: 16pt 이상 굵은 한글·영문 헤드라인, 숫자 단순 표기, 한 컷에 헤드라인+서브+버튼.
- 약하다: 8pt 이하 본문, 50자 이상 단락, 가격·전화번호·날짜의 정확성, 손글씨 한글.
- 따라서 이미지엔 헤드라인·짧은 라벨만, 본문·가격·조건은 HTML 텍스트로. 첫 결과가 깨지면 "굵은 고딕, 대형 크기"를 명시해 1~2회 재생성한다. HTML/CSS 후합성으로 도피하지 않는다(사용자가 명시 요청할 때만).
